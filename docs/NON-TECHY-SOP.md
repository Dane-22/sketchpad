## 1. Account Approvals

To maintain the security of our projects and data, the Sketchpad System requires all new user registrations to be manually approved by an Administrator.

### The Approval Workflow
1. When a new team member or client signs up, their account is placed in a **Pending** state. They will not be able to log in or view projects yet.
2. An Administrator will receive a notification of a new pending account.
3. The Administrator will review the request to ensure the user is recognized and assigned the correct role (e.g., Engineer vs. Client).
4. **Approval:** The Administrator clicks "Approve" on the user dashboard. The user can now log in.
5. **Rejection:** If the account is unauthorized, the Administrator will click "Reject" and provide a brief reason for the rejection.

## 2. Project Governance

Maintaining a clean and organized workspace is essential as the number of projects grows.

- **Creating Projects:** Ensure all new projects have a clear, descriptive title and a summary of the project goals in the description.
- **Public vs. Private:** By default, projects are private. Only set a project to "Public" if the information is safe to be viewed by anyone with the link.
- **Archiving Projects:** When a project is completed and handed off to the client, a manager should mark the project as "Archived". This removes it from the active dashboard but keeps the data safe for historical reference.

## 3. Communication Standards

To ensure nothing gets lost in translation, please follow these guidelines when communicating within the Sketchpad System:

- **Use the Right Channel:** Keep general banter in `#general`, and use specific channels (like `#plumbing` or `#site-plan`) for focused discussions.
- **Pin Canvas Comments for Specifics:** If you are asking a question about a specific object on the drawing, use the Canvas Comment tool to place a pin directly on the object. This avoids confusion about what you are referring to.
- **Resolve Comments:** Once a question or issue raised in a canvas comment has been addressed, mark the comment thread as "Resolved" so others know the issue is closed.

## 4. Support Workflows

> [!IMPORTANT]
> Since we are currently in the testing phase of this project, all bugs and errors should be reported to the Developer (Daniel Rillera) immediately.

If users encounter issues or bugs while using the platform, follow this escalation path:

1. **Basic Checks:** Ensure the user has tried refreshing their browser and clearing their cache. 
2. **Browser Support:** Verify they are using a modern, updated web browser (Chrome, Edge, or Firefox).
3. **Escalation:** If the issue persists (e.g., drawings won't load, or the chat is broken), gather the following information and report it directly to Daniel Rillera:
   - The user's name and email.
   - The specific Project ID they were working in.
   - A description of what they were trying to do.
   - Any error messages they saw on the screen.
